# Agent Liquidity Copilot

> Built for **AI Dev Fest 2026** (DIU-CPC × upay) | Track 05: Merchant & Agent Intelligence

**Live demo:** https://agentliquidity.streamlit.app/

## Overview

MFS agents often run out of cash or e-float at peak hours. Each stockout means lost cash-out transactions and unhappy customers.

**Agent Liquidity Copilot** is an AI assistant that:
1. Forecasts hourly cash-out demand for an agent.
2. Compares the forecast with the agent's current cash.
3. Recommends when and how much to rebalance, before a stockout happens.
4. Explains each recommendation in plain English or Bangla.

**Problem statement:** For MFS agents in semi-urban and rural areas, running out of cash or e-float at peak hours causes lost cash-out transactions and unhappy customers. We built an agent liquidity copilot that uses synthetic transaction history to forecast hourly cash-out demand and recommend when and how much to rebalance, with success measured by the reduction in simulated stockout events versus a naive baseline.

**Data privacy:** This project uses only synthetic data generated by our own script. No real customer or agent data (PII) is used anywhere.

## Results

Test window: 28 days (Sept 1-28, 2026), 20 synthetic agents, 7,280 agent-hours. The model never saw this period during training.

**Forecast accuracy** (hourly cash-out demand)

| Model | MAE (BDT) | MAPE |
|---|---|---|
| Baseline: same hour last week | 6,217 | 35.2% |
| LightGBM | 3,812 | 22.0% |

LightGBM reduces forecast error by 38.7%.

**Stockout simulation** (same rules and opening cash for every strategy, only the forecast differs)

| Strategy | Stockout hours | Service level | Cash moved (BDT) |
|---|---|---|---|
| No rebalancing | 3,456 (47.5%) | 47.5% | 0 |
| Rules + baseline forecast | 193 (2.7%) | 99.1% | 81.5M |
| Rules + LightGBM forecast | 18 (0.2%) | 99.9% | 79.3M |

Switching from the baseline forecast to LightGBM cuts stockout hours by 91% while moving about 2.6% less cash. The comparison against "no rebalancing" depends on our assumed opening cash, so the baseline-vs-LightGBM comparison is the fairer one.

**Assumptions and limits**
- Data is synthetic, with built-in peak-hour, Friday, salary-period and festival patterns plus random noise.
- Agents open each day with cash equal to 6x their average hourly demand.
- A rebalance arrives 1 hour after it is ordered.
- The simulation assumes the agent approves every recommendation. Real approval rates will be lower.
- The simulation averages about 6 top-ups per agent per day, which may be too many in practice. Batching them is a natural next step.

## Features

- Synthetic data generator with realistic patterns (peak hours, Fridays, salary-cycle days, festival spikes)
- Baseline forecast ("same hour last week") and a LightGBM forecasting model
- Business-rules layer, kept separate from the ML model, that turns forecasts into rebalance recommendations
- Stockout simulation that compares no rebalancing, baseline-driven rules and model-driven rules
- Interactive Streamlit dashboard with forecast charts, recommendations and a results tab
- Plain-language explanations in English and Bangla, generated from templates (works offline)
- Optional LLM rewording that is rejected automatically if it changes any number
- Human oversight: the agent approves or rejects every recommendation, and decisions are logged

## Setup / Run

**Requirements:** Python 3.10 or newer, and Git.

```bash
# 1. Clone the repository
git clone https://github.com/tareq-x/agent-liquidity-copilot.git
cd agent-liquidity-copilot

# 2. Create and activate a virtual environment
python -m venv venv
# Windows:
venv\Scripts\activate
# Mac/Linux:
source venv/bin/activate

# 3. Install dependencies (full pipeline)
pip install -r requirements-train.txt
```

**Run the full pipeline** (the generated files are already committed, so you can skip straight to the dashboard):

```bash
python generate_data.py     # creates data/synthetic_cashout.csv
python train_model.py       # trains LightGBM, writes data/test_predictions.csv
python simulate.py          # writes data/simulation_results.csv
streamlit run app.py        # opens the dashboard at http://localhost:8501
```

To run only the dashboard, `pip install -r requirements.txt` is enough.

## Environment Variables

None are required. Without a key, the app uses template-based explanations.

| Variable | Purpose |
|---|---|
| `LLM_API_KEY` | Optional. Enables LLM rewording of explanations. Requires `pip install anthropic`. |
| `LLM_MODEL` | Optional. Overrides the default model name. |

Set them as environment variables, for example in PowerShell: `$env:LLM_API_KEY="your_key"`. On Streamlit Community Cloud, add `LLM_API_KEY = "your_key"` under Settings > Secrets. Never commit keys to the repository.

## Responsible AI Notes

- **Explainable:** every recommendation shows the forecast, the cash needed and the reason it was made.
- **Human in the loop:** agents approve or decline each action. Nothing is automatic.
- **Private:** synthetic data only.
- **Separation of concerns:** the ML model predicts demand, and transparent business rules decide actions. Decision logic is not hidden inside an LLM prompt.
- **LLM guardrail:** the optional LLM only rewords text. If it changes any number, its output is discarded and the template is used.
